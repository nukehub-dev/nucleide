# Validation AGENTS.md

## Purpose

Cross-code validation harness comparing Nucleide against PyNE and OpenMC on
shared inputs, plus coarse timing comparisons. Its committed results are quoted
by the JOSS paper (`paper.md`).

## Ownership

This file owns the validation harness workflow: scripts, the committed
reference tally (`magic_tally.txt`), and the committed results document.

## Local Contracts

- `results.md` and `validation/results/*.json` are **generated artifacts**:
  never hand-edit them. Regenerate by running `run_all.sh` (or
  `run_container.sh`). Probe-only reports are generated by the documented
  pinned-image command after the main run; then rerun `render_results.py` and
  `make_figures.py` in the canonical environment. Cosmetic fixes that do not
  alter numbers belong in `render_results.py` or `common.py`.
- Report prose uses single asterisks literally for formulas and wildcards;
  use backticks for code and double asterisks for bold. The renderer escapes
  literal asterisks outside code spans before wrapping paragraphs.
- Table rows must have exactly as many cells as their headers, including
  unavailable-oracle rows; fix malformed producers rather than padding output.
- `validation/figures/*.png` are **generated artifacts** (from
  `make_figures.py`): never hand-edit them. Unlike `results.md` they are
  committed so `paper.md` can reference them; regenerate and recommit whenever
  the harness reruns.
- `validation/.cache/` owns git-ignored runtime downloads, source-pinned
  probe caches, and local run/benchmark receipts. Never commit its contents;
  publish verified comparisons through generated reports. Document provenance
  in `validation/README.md` when adding a new download.
- `validation/environment.json` is the **only hand-maintained input** for the
  environment table; keep it up to date when the container or dependency
  channels change.
- New oracle scripts (`*_vs_*.py`) are auto-discovered by `run_all.sh` with
  no wiring; register each report name in `render_results.py`
  `SECTION_ORDER` (it errors on missing reports) and record new oracle
  dependencies in `environment.json`.
- Every number quoted in `paper.md` must come from a recorded `run_all.sh` run.
- Scripts must pass `ruff format --check` and `ruff check` (repo
  `pyproject.toml` settings, line-length 100).
- Do not add fixtures here that duplicate `fixtures/` policy; the harness reads
  from `fixtures/` and patches only at runtime, in memory.
- Oracle comparisons (`parsers_vs_refs.py`) must never skip silently: every
  skip is printed and recorded in the report prose with its reason.
- Probe-only external oracles that need a separate image
  (`validation/tritium_vs_festim.py`: Docker + digest-pinned DOLFINx image,
  `festim==2.1`) run outside the main `Containerfile` — their legs SKIP
  loudly when the oracle is unavailable and never add FESTIM/FEniCS to the
  validation container.
- F5 recombination uses atomic-unit conversion with exact SI Avogadro
  constant, the two-reactant coefficient `Kr/(2 NA)`, quadratic elements,
  independent three-level mesh/time refinement and exported-history mass
  balance. Preserve F1–F4 gates. Missing FESTIM is SKIP; installed/broken oracle environments and
  configured solver/export errors fail for every leg. Unconverged F5 refinement is INCONCLUSIVE
  and exits nonzero. Image/package pins and execution limits live in
  `validation/README.md`; never claim an unexecuted F5 pass. Resolve startup
  before nominal time-step refinement. Reduced-run caches under `.cache/`
  require source/facade/extension hashes, parameters and environment identity;
  recompute acceptance gates on reuse. Prefer an installed rebuilt release
  wheel; bootstrap a checkout extension only when the package is absent.
- `actinv_handoff_probe.py` is an optional synthetic exchange check, separate
  from `*_vs_*.py` physics comparisons. Require an explicit hash-pinned CLI,
  bound the leaf export process wait, retain JSON receipts under `.cache/`,
  and never download evaluated data or claim an activation solve from it.
- Fresh ACTINV activation comparisons execute the source-pinned external
  example separately from the synthetic probe. Retain original/compatible
  script hashes and diff, verified data hashes, compiled-extension identity,
  and direct-versus-translated results under `.cache/`. Catalog compatibility
  changes must preserve physical inputs and acceptance thresholds; report
  same-solver interoperability separately from independent physics validation.

- Native timing rows must identify actual Criterion artifact hashes or label
  historical fallback estimates explicitly. Present but malformed/nonfinite
  benchmark artifacts fail; never silently substitute reference constants.

## Work Guidance

- Canonical environment is the container built from `Containerfile`
  (`./validation/run_container.sh`, Docker or Podman): Python 3.12,
  PyNE 0.7.5 from conda-forge, OpenMC 0.16.0 built from the upstream tag,
  serpentTools 0.11.0 from PyPI, and the Nucleide abi3 release wheel built by
  the `ghcr.io/pyo3/maturin` container. Version-pin rationale is documented in
  the `Containerfile` header; update it when conda-forge catches up (PyNE >
  0.7.5 or OpenMC >= 0.16.0).
- `run_container.sh` selects installed Podman, then Docker; an explicit
  `CONTAINER_ENGINE=docker|podman` selects one engine without silently
  switching after a configured failure. Both execute the same Containerfile
  and harness. Limit runtime jobs to 6 GiB RAM/no swap, 128 tasks and 2 CPUs;
  OpenMC and Rust builds use two compilation jobs. Build context is validation/.
- A conda env fallback also works:
  (`mamba create -p ~/.conda/envs/nuke-validation -c conda-forge pyne openmc`)
  with the Nucleide release wheel installed into that env
  (`maturin build --release`, then `pip install --force-reinstall target/wheels/nucleide-*.whl`).
- Run: `./validation/run_container.sh`, or `./validation/run_all.sh [python-binary]`
  against any prepared Python.
- PyNE is typically built without PyMOAB; the MAGIC comparison falls back to a
  formula-equivalent pure-Python reference and must say so in `results.md`.

## Verification

- `run_all.sh` exits nonzero on failure; all scripts must complete.
- Repo-wide markdown lint (`npx markdownlint-cli2 "validation/*.md"`) must be
  clean.
